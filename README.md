## The craft

I treat frontend as a craft, and I build things to last. Twenty-three years in, I've watched plenty of trends come and go, so I start with the web platform itself: solid HTML, well-built CSS, and JavaScript where it genuinely adds something. That's what keeps a site accessible, fast and easy to maintain for years after launch, not just on the day it goes live.

- **HTML.** Semantic, well-structured markup (POSH: Plain Old Semantic HTML). The core of the craft.
- **CSS.** Decades of writing maintainable CSS that works for teams, not just the person who wrote it. Modern CSS, including cascade layers (`@layer`), container queries and custom properties, enhances an already solid base rather than replacing it.
- **Progressive enhancement.** HTML-first, so it works for everyone, then layered up with JavaScript and TypeScript.
- **Accessibility.** WCAG AA as the baseline, built in from the start rather than audited on at the end.
- **Web performance.** I love making things fast: lean pages, small payloads, and Core Web Vitals that hold up on a real phone over a real connection. The same goes for builds and deploys.
- **Search and discoverability.** The geeky stuff that makes sites findable: microformats (I was there for those too), structured data with schema.org, clean metadata and technical SEO, through to analytics and Search Console. For my own clients, I've set up automated audits that turn SEO, accessibility and performance checks into an actionable report I can make decisions from.
- **Testing and quality.** Cross-browser and cross-device, every time.
- **Detail, then ship.** I'm detail-oriented, but not afraid to ship lean and refine from there.
- **Motion earns its place.** If it doesn't help, it doesn't go in.
- **Design systems.** I shape the architecture: tokens and components that scale across many sites. Designers lead the look.
- **Headless CMS architecture.** Content models and frontends for Storyblok, Prismic and Contentful that editors can actually use.
- **Stack of choice.** Astro first, on Netlify with Storyblok, usually instead of a React SPA. Eleventy or Shopify when they fit better.

## Shaped by the browser wars

I got into web development through Counter-Strike, building websites for clans and a gaming league, first in Microsoft FrontPage and Dreamweaver, then hand-coding in BBEdit with PHP and MySQL. That was during the browser wars: IE5.5, IE6 and IE7 on Windows, IE5 and Camino on the Mac, plus early Opera and Firefox back when it was still called Firebird. Back then you wrote CSS aimed at one specific version of one browser, and a layout that worked in one could fall apart in the next.

That shaped how I QA today:

- **Never trust one browser.** If it only looks right where it was built, it isn't finished. I check across browsers as a matter of course, not at the end.
- **Test on real devices.** Emulators and a resized window tell you how something looks, not how it feels. Scrolling, tapping, typing and load times only show up on real phones and tablets in your hand.
- **Build a baseline that can't break.** Progressive enhancement started as a survival tactic. If a feature isn't supported, the core experience still works.
- **Standards over hacks.** I've written enough browser-specific hacks to know what they cost later. Building on web standards is what lets a site keep working for years.
